When scaling workflow automation and AI agent orchestration, off-the-shelf SaaS tiers can rapidly hit strict execution boundaries or per-workflow monthly costs. 

To solve this, I designed a resilient, self-hosted deployment architecture for **n8n** running on **Azure Container Apps (ACA)** backed by an Azure Database for PostgreSQL serverless instance.

## Architecture Overview

Here is how the webhook payload flows from incoming HTTP triggers through to execution and notification:

1. **Client / Webhook Trigger**: External webhooks (GitHub, forms, Slack) hit the custom domain endpoint.
2. **Azure Container App**: Spins up or scales worker instances dynamically depending on current execution queues.
3. **PostgreSQL & Redis**: Retains workflow execution logs, node states, and schedule timers.

## Key Benefits of Azure Container Apps for Workflows

- **Scale to Zero**: When idle during overnight periods, compute costs drop to virtually zero.
- **Persistent Storage Mounts**: Using Azure Files mounts for persistent `.n8n` configuration.
- **Custom AI Nodes**: Direct execution of custom Python scripts and LangChain / LlamaIndex agent tools inside worker containers.

## Summary & Key Takeaways

Self-hosting gives complete sovereignty over your data, removes artificial execution rate caps, and allows seamless integration with private LLMs and internal microservices.
